# 刷刷鸭 — User Stories

## EP1: 照片清理

### US-CP-01 随机浏览照片

**背景**：用户相册积累了大量照片，逐一翻阅太耗时，需要一种轻松的方式快速决定去留。

**用户故事**：作为手机用户，我希望 App 能从我的相册中随机选出一批照片逐一展示给我，让我不用翻遍相册就能开始清理。

**AC**：
- Given 用户相册中有 100+ 张照片
- When 用户在首页点击"随机清理照片"
- Then App 随机选出若干张照片（默认 10 张），进入浏览页逐一展示
- And 每张照片显示文件名、大小、拍摄日期
- And 顶部显示当前进度（如 3/10）

**AC**：
- Given 用户相册中仅有 3 张照片，设置为每轮 10 张
- When 用户点击"随机清理照片"
- Then App 展示全部 3 张，顶部提示"仅找到 3 张"

**AC**：
- Given 用户相册为空
- When 用户点击"随机清理照片"
- Then 展示空状态页面，提示"相册空空如也"，可返回首页

### US-CP-02 保留或删除照片

**背景**：用户需要对每张照片做出"保留"或"删除"的决定，且操作要简单直观。

**用户故事**：作为正在浏览照片的用户，我希望能对每张照片快速做出保留或删除的决定，操作后自动跳到下一张。

**AC**：
- Given 用户正在浏览页查看第 3 张照片
- When 用户点击"保留"按钮（或右滑/上滑，取决于交互模式）
- Then 该照片标记为"保留"，自动跳到第 4 张

**AC**：
- Given 用户正在浏览页查看第 5 张照片
- When 用户点击"删除"按钮（或左滑，取决于交互模式）
- Then 该照片标记为"待删除"（不立即删除），自动跳到第 6 张

**AC**：
- Given 某张照片无法加载（文件损坏）
- When 用户滑到该照片
- Then 显示占位图和提示"无法加载此照片"，保留/删除按钮仍可操作

### US-CP-03 确认删除与查看结果

**背景**：用户需要在最终删除前有明确的确认机会，避免误删。删除**前**的结果页必须让用户清楚地意识到"还没删、需要我确认"，而不是一进入就显示"本轮清理完成"，让人误以为已经删完。删除前与删除后是两个语义截然不同的状态。

**用户故事**：作为完成一轮浏览的用户，我希望先看到一个清晰的"待确认删除"界面（明确告诉我还没删除），只有在我确认且删除成功后，界面才变为"本轮清理完成"。

**AC（待确认态 — 删除前）**：
- Given 用户浏览完全部照片，其中 4 张标记为"待删除"
- When 刚进入结果页、尚未点击"确认删除"
- Then 页面处于待确认状态，标题显示"即将删除 4 项"，页面不出现"本轮清理完成"字样
- And 统计以待定口吻呈现：待删除 4 张 / 拟保留 6 张 / 可释放 X MB
- And 展示待删除照片的缩略图列表，用户可取消某些项的删除标记
- And 显示醒目的"确认删除"按钮，并提示"删除后不可在 App 内撤销"

**AC（完成态 — 删除后）**：
- Given 用户在待确认态点击"确认删除"
- When 系统弹出 1 次确认弹窗（系统级），用户确认后照片移至系统回收站、删除成功
- Then 页面切换为完成状态，标题显示"本轮清理完成"
- And 统计以已完成口吻呈现：已删除 X 张 / 已保留 6 张 / 已释放 X MB
- And 不再显示"确认删除"按钮和待删除缩略图列表

**AC（无待删除项直接完成）**：
- Given 用户浏览完照片但未标记任何"待删除"（全部保留）
- When 进入结果页
- Then 直接显示完成状态"本轮清理完成"，删除 0 张

**AC**：
- Given 用户在系统确认弹窗中点击"取消"
- When 弹窗关闭
- Then 所有照片保留，提示"已取消删除"

**AC**：
- Given 用户确认删除，但部分照片因权限不足无法删除
- When 删除操作完成
- Then 结果页显示实际删除成功的数量和失败的数量
- And 失败的照片仍保留在相册中

**AC**：
- Given 用户完成本轮后想继续
- When 点击"再来一轮"
- Then 随机选取新一批照片（与本次会话已展示的不重复），进入浏览页
- And 当所有照片都已展示过时，提示"所有照片都看过了，重新开始"

## EP2: 视频清理

### US-CP-04 随机浏览视频

**背景**：视频文件通常体积更大，清理视频能更有效地释放存储空间。

**用户故事**：作为手机用户，我希望 App 能随机选出一批视频供我浏览和清理，操作方式和照片清理一致。

**AC**：
- Given 用户设备有 50+ 个视频
- When 用户在首页点击"随机清理视频"
- Then App 随机选出若干个视频，进入浏览页逐一展示
- And 每个视频显示缩略图、时长、文件大小、拍摄日期

### US-CP-05 预览视频

**背景**：用户需要播放视频才能判断是否值得保留。

**用户故事**：作为正在浏览视频的用户，我希望能在任何交互模式下预览播放视频内容，并控制声音，以便做出保留或删除的判断。

**AC**：
- Given 用户在轮播模式下查看视频
- When 用户点击视频缩略图
- Then 视频在当前卡片内联播放，默认静音
- And 卡片上显示静音切换按钮，可开启/关闭声音

**AC**：
- Given 用户在卡片滑动模式下查看视频
- When 用户点击视频缩略图
- Then 视频在当前卡片内联播放，默认静音
- And 卡片上显示静音切换按钮，可开启/关闭声音

**AC**：
- Given 用户在全屏模式下滑到视频项
- When 视频出现在屏幕中
- Then 自动静音播放
- And 底部显示静音切换按钮，可开启/关闭声音

**AC**：
- Given 视频文件无法播放（格式不支持或损坏）
- When 用户滑到该视频
- Then 显示占位图 + "无法播放此视频"，提供"跳过"按钮

### US-CP-06 确认删除视频

**背景**：视频删除的确认流程与照片一致——删除**前**的结果页必须让用户清楚地意识到"还没删、需要我确认"，而不是一进入就显示"本轮清理完成"。视频文件通常更大，误删代价更高，确认中间态尤为重要。

**用户故事**：作为完成一轮视频浏览的用户，我希望先看到一个清晰的"待确认删除"界面（明确告诉我还没删除），只有在我确认且删除成功后，界面才变为"本轮清理完成"。

**AC（待确认态 — 删除前）**：
- Given 用户浏览完全部视频，其中 3 个标记为"待删除"
- When 刚进入结果页、尚未点击"确认删除"
- Then 页面处于待确认状态，标题显示"即将删除 3 项"，页面不出现"本轮清理完成"字样
- And 统计以待定口吻呈现：待删除 3 个 / 拟保留 7 个 / 可释放 X MB
- And 展示待删除视频的缩略图列表，用户可取消某些项的删除标记
- And 显示醒目的"确认删除"按钮，并提示"删除后不可在 App 内撤销"

**AC（完成态 — 删除后）**：
- Given 用户在待确认态点击"确认删除"
- When 系统弹出 1 次确认弹窗（系统级），用户确认后视频移至系统回收站、删除成功
- Then 页面切换为完成状态，标题显示"本轮清理完成"
- And 统计以已完成口吻呈现：已删除 X 个 / 已保留 7 个 / 已释放 X MB
- And 不再显示"确认删除"按钮和待删除缩略图列表

**AC（无待删除项直接完成）**：
- Given 用户浏览完视频但未标记任何"待删除"（全部保留）
- When 进入结果页
- Then 直接显示完成状态"本轮清理完成"，删除 0 个

**AC**：
- Given 用户在系统确认弹窗中点击"取消"
- When 弹窗关闭
- Then 所有视频保留，提示"已取消删除"

**AC**：
- Given 用户确认删除，但部分视频因权限不足无法删除

## EP3: 主题与个性化

### US-CP-07 切换视觉主题 ⚙️ 进行中

**背景**：用户（尤其女性用户）重视 App 的视觉体验，希望能选择喜欢的风格。每个主题不只是换颜色，而是提供完全不同的界面体验——不同的布局结构、图标风格、动画节奏——切换主题就像换了一个 App。

**用户故事**：作为用户，我希望能从 5 种风格截然不同的主题中选择，每个主题有自己独特的页面布局和视觉风格，让整个 App 从闪屏到每一个页面都呈现统一的主题氛围。

**AC**：
- Given 用户进入设置页
- When 浏览主题预览卡片，点击"大胆几何"主题
- Then 设置页本身立即变为暗色背景、渐变色块风格
- And 返回首页后，首页变为双卡片并排布局
- And 进入浏览页后，按钮变为渐变填充风格
- And 闪屏、结果页等所有页面均跟随该主题

**AC**：
- Given 用户当前使用"温暖手工感"主题（列表卡片布局）
- When 切换到"克制极简"主题
- Then 首页布局从列表卡片变为分段切换+单按钮
- And 图标风格从圆润线条变为纤细直线
- And 字体、圆角、阴影等视觉参数全部同步变化

**AC**：
- Given 用户选择了某主题后关闭 App
- When 重新打开 App
- Then 主题保持为上次选择的，闪屏也展示对应主题的动画

**AC**：
- Given App 从旧版本升级，用户之前选择了已不存在的旧主题
- When 用户打开升级后的 App
- Then 自动回退到默认主题（温暖手工感），正常使用

### US-CP-07a 精致矢量图标体验

**背景**：App 的所有图标当前使用 emoji 字符，在不同设备上显示不一致，且给人"AI 生成"的廉价感。用户期望看到精心设计的矢量图标。

**用户故事**：作为用户，我希望 App 中的所有图标都是精心绘制的矢量图形，风格与当前主题统一，而不是系统 emoji。

**AC**：
- Given 用户使用任意主题
- When 在任何页面看到操作图标（返回、删除、保留、设置、播放等）
- Then 所有图标都是矢量绘制的线条图标，而非 emoji 字符
- And 图标的线宽、颜色、端点样式与当前主题一致

**AC**：
- Given 用户使用"杂志排版"主题
- When 在浏览页查看操作按钮
- Then 删除按钮显示为纤细的垃圾桶图标 + "DISCARD" 文字标签
- And 保留按钮显示为纤细的勾选图标 + "KEEP" 文字标签

**AC**：
- Given 用户使用"大胆几何"主题
- When 在浏览页查看操作按钮
- Then 删除按钮显示为粗线条垃圾桶图标 + 渐变红色填充背景
- And 保留按钮显示为粗线条勾选图标 + 渐变绿色填充背景

### US-CP-08 切换交互模式

**背景**：不同用户有不同的交互偏好，提供多种浏览方式增强体验。

**用户故事**：作为用户，我希望能选择喜欢的照片浏览交互方式（相册轮播、卡片滑动或全屏浏览）。

**AC**：
- Given 用户在设置页选择"卡片左右滑"模式
- When 开始新一轮照片清理
- Then 浏览页以卡片堆叠方式展示，左滑=删除、右滑=保留

**AC**：
- Given 用户切换交互模式后
- When 模式变更立即保存
- Then 下次打开 App 时保持该模式

### US-CP-09 动效与减少动效

**背景**：部分用户对动画敏感，系统提供了"减少动态效果"偏好。

**用户故事**：作为对动画敏感的用户，我希望 App 能尊重系统的"减少动态效果"设置。

**AC**：
- Given 系统开启了"减少动态效果"偏好
- When 用户使用 App
- Then 背景粒子动画、按钮弹跳动效等装饰性动画关闭，仅保留必要的页面切换

## EP4: 设置与偏好

### US-CP-10 调节每轮数量

**用户故事**：作为用户，我希望能调节每轮随机选取的数量。

**AC**：
- Given 用户在设置页将数量调为 5
- When 开始新一轮清理
- Then 仅随机选取 5 张，进度显示 N/5

### US-CP-11 权限引导

**用户故事**：作为首次使用的用户，我希望 App 能清晰说明为什么需要相册权限，并在权限被拒后引导我解决。

**AC**：
- Given 用户首次点击开始
- When 系统弹出权限请求
- Then 权限说明文案清晰表述"用于读取和清理您的照片/视频"

**AC**：
- Given 用户永久拒绝了权限
- When 用户再次尝试开始
- Then 展示引导页，说明需要权限，提供"去设置"按钮跳转系统设置

**AC**：
- Given 用户仅授权了部分照片（iOS 14+ / Android 14+）
- When 用户使用 App
- Then 首页显示提示条"当前仅能访问部分照片"，引导授权全部

## EP5: 浏览体验增强

### US-CP-12 中途退出浏览

**背景**：用户在浏览照片或视频过程中，可能临时有事或改变主意，需要随时退出当前浏览回到首页。目前仅全屏模式有退出按钮，轮播和卡片模式缺少明确的退出入口。

**用户故事**：作为正在浏览照片或视频的用户，我希望在任何交互模式下都能看到明确的退出按钮，随时中途退出浏览回到首页。

**AC**：
- Given 用户在轮播模式下浏览照片或视频
- When 用户点击退出按钮
- Then 立即退出浏览页，回到首页
- And 本轮已做的标记全部丢弃，不进入结果页

**AC**：
- Given 用户在卡片滑动模式下浏览照片或视频
- When 用户点击退出按钮
- Then 立即退出浏览页，回到首页
- And 本轮已做的标记全部丢弃，不进入结果页

**AC**：
- Given 用户在全屏模式下浏览照片或视频
- When 用户点击退出按钮（已有"← 退出"）
- Then 立即退出浏览页，回到首页
- And 本轮已做的标记全部丢弃，不进入结果页

### US-CP-18 点击全屏查看媒体

**背景**：在"轮播相册式"和"卡片左右滑"模式下，照片和视频以缩略卡片展示，用户常需看清细节（照片是否清晰、视频实际内容）才能更好地决定去留。

**用户故事**：作为正在清理的用户，我希望点击当前的照片或视频将其放大到全屏查看，看清细节后再决定删除或保留。

**AC**：
- Given 用户在轮播相册式模式下浏览照片或视频
- When 用户点击当前展示的照片
- Then 该照片以全屏铺满展示，并提供删除、保留与返回操作

**AC**：
- Given 用户在卡片左右滑模式下浏览照片或视频
- When 用户点击当前展示的视频
- Then 该视频以全屏展示并可播放，并提供删除、保留与返回操作

**AC**：
- Given 用户正在全屏查看某个媒体
- When 用户点击删除或保留
- Then 该媒体的标记生效，全屏关闭并回到原模式，浏览推进到下一项

**AC**：
- Given 用户正在全屏查看某个媒体
- When 用户点击返回
- Then 全屏关闭，回到原模式的当前位置，不改变任何标记

**AC**：
- Given 用户的交互模式为"全屏上下滑"
- When 用户点击媒体
- Then 不重复进入全屏（该模式下媒体本就全屏展示）

### US-CP-19 撤销上一步重新决策

**背景**：用户在快速清理时可能误删或误留某个媒体，需要反悔的机会逐个回到之前的媒体重新选择，且不限于只撤一次。

**用户故事**：作为正在清理的用户，我希望连续撤销之前对媒体做出的删除/保留决策，一路回退直至本轮第一个媒体，重新决定去留。

**AC**：
- Given 用户刚对某个媒体做出删除或保留决策并进入了下一个
- When 用户点击撤销
- Then 回到上一个媒体，其删除/保留标记被清除、恢复为待决策状态

**AC**：
- Given 用户已连续对多个媒体做出决策
- When 用户多次点击撤销
- Then 逐个回退到之前的媒体并清除其标记，可一路回退直至本轮第一个媒体

**AC**：
- Given 用户已回退到本轮第一个媒体
- When 用户查看撤销操作
- Then 撤销操作不可用（没有更早的媒体可回退）

**AC**：
- Given 用户在本轮还未做出任何删除/保留决策
- When 用户查看撤销操作
- Then 撤销操作不可用

**AC**：
- Given 用户分别处于轮播相册式、卡片左右滑、全屏上下滑三种模式之一
- When 用户已做出至少一次决策
- Then 三种模式均提供可用的撤销操作

## EP6: 自动升级

### US-CP-13 启动时检查更新

**背景**：App 没有上架应用商店，用户无法通过商店自动获取更新，需要 App 自身检测是否有新版本。作为开源项目，部分用户可能自行编译使用，不需要自动升级功能。

**用户故事**：作为用户，我希望 App 启动时能自动检测是否有新版本可用，并在有更新时提醒我；同时我可以选择关闭这个功能。

**AC**：
- Given 用户开启了"自动检查更新"（默认开启）且版本不是最新，且该更新是可选更新
- When 用户打开 App
- Then 弹出更新提示弹窗，显示新版本号和更新日志
- And 弹窗提供"立即更新"和"稍后提醒"两个按钮
- And 用户可以点击"稍后提醒"关闭弹窗，正常使用 App

**AC**：
- Given 用户开启了"自动检查更新"且版本不是最新，且该更新是强制更新
- When 用户打开 App
- Then 弹出全屏更新提示，显示新版本号和更新日志
- And 仅提供"立即更新"按钮，不可关闭或跳过
- And 用户必须更新才能继续使用 App

**AC**：
- Given 用户已经在使用最新版本
- When 用户打开 App
- Then 不弹出任何更新提示，正常进入首页

**AC**：
- Given 用户设备无网络连接
- When 用户打开 App
- Then 不弹出更新提示，正常进入首页（静默失败）

**AC**：
- Given 用户关闭了"自动检查更新"
- When 用户打开 App
- Then 不进行任何版本检查，直接进入首页

### US-CP-16 开关自动检查更新

**背景**：作为开源项目，部分用户自行编译安装，不需要自动升级提醒；也有用户希望减少不必要的网络请求。

**用户故事**：作为用户，我希望能在设置页自由开关"自动检查更新"功能。

**AC**：
- Given 用户进入设置页
- When 查看更新相关设置
- Then 看到"自动检查更新"开关，默认开启

**AC**：
- Given 用户关闭"自动检查更新"
- When 下次启动 App
- Then 不再自动检查版本，设置页"检查更新"按钮仍可用（手动检查不受影响）

**AC**：
- Given 用户重新开启"自动检查更新"
- When 下次启动 App
- Then 恢复启动时自动检查

### US-CP-14 手动检查更新与版本提示

**背景**：用户可能想主动确认当前是否为最新版本。同时，如果启动时已检测到新版本，设置页应直观展示更新提示，让用户不会错过。

**用户故事**：作为用户，我希望在设置页能直观看到是否有新版本可用，并能手动检查更新。

**AC**：
- Given 启动时已检测到有新版本可用
- When 用户进入设置页
- Then "检查更新"按钮旁显示红点或"新版本"标记
- And 显示新版本号（如"v1.2.0 可用"）

**AC**：
- Given 用户进入设置页
- When 用户点击"检查更新"按钮
- Then 显示加载状态，检查完成后提示检查结果

**AC**：
- Given 有新版本可用
- When 检查完成
- Then 显示更新弹窗，包含新版本号和更新日志，可选择"立即更新"

**AC**：
- Given 当前已是最新版本
- When 检查完成
- Then 提示"已是最新版本"

**AC**：
- Given 无网络连接
- When 用户点击"检查更新"
- Then 提示"网络不可用，请稍后再试"

### US-CP-15 下载并安装更新

**背景**：不同操作系统的安装方式不同，Android 可以直接下载安装包，iOS 和 HarmonyOS 需要跳转到对应的下载页面。

**用户故事**：作为用户，我希望点击"立即更新"后，App 能引导我完成更新安装，过程尽可能简单。

**AC**：
- Given 用户在 Android 设备上点击"立即更新"
- When 开始下载
- Then App 内显示下载进度条
- And 下载完成后自动弹出系统安装界面

**AC**：
- Given 用户在 iOS 设备上点击"立即更新"
- When 开始更新
- Then 跳转到浏览器打开下载页面

**AC**：
- Given 用户在 HarmonyOS 设备上点击"立即更新"
- When 开始下载
- Then App 内显示下载进度条
- And 下载完成后自动弹出系统安装界面

**AC**：
- Given 下载过程中网络中断
- When 下载失败
- Then 提示"下载失败，请检查网络后重试"，提供"重试"按钮

### US-CP-17 商店版无应用内升级

**背景**：刷刷鸭计划上架华为、小米、OPPO 等国内应用商店。这些商店禁止应用内自更新（审核要求），版本分发与升级由商店承担。另一方面，通过 GitHub Release 直接下载 APK 的用户仍需要应用内升级提示。因此同一份代码需要产出两种面向不同分发渠道的安装包：**直装版**（含应用内升级）与**商店版**（完全不含应用内升级）。

**用户故事**：作为通过应用商店安装刷刷鸭的用户，我希望 App 不出现任何"应用内检查更新""下载新版本"等入口，版本升级完全由商店负责，刷刷鸭不发起任何升级相关的网络请求，确保隐私与合规。

**AC**：
- Given 用户安装的是商店版刷刷鸭
- When 用户打开设置页
- Then 设置页不显示"自动检查更新"开关、"检查更新"按钮、"版本可用"提示等任何升级相关条目

**AC**：
- Given 用户安装的是商店版刷刷鸭
- When 刷刷鸭启动完毕进入首页
- Then 刷刷鸭未向任何升级 API 发起网络请求（可通过抓包验证无相关流量）

**AC**：
- Given 用户安装的是商店版刷刷鸭
- When 刷刷鸭正常运行
- Then 永远不会出现"发现新版本""需要更新""下载进度"等升级相关弹窗

**AC**：
- Given 用户安装的是通过 GitHub Release 下载的直装版刷刷鸭
- When 用户使用刷刷鸭
- Then US-CP-13 ~ US-CP-16 的升级行为全部保持不变
